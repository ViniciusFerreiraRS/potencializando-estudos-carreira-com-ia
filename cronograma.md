# Cronograma de estudos — 30 dias

**Área:** Desenvolvimento de software e automação  
**Disponibilidade considerada:** aproximadamente 1 hora por dia.

O cronograma é uma orientação flexível. Reserve parte do tempo para estudar o conteúdo e parte para praticar. Se um tópico exigir mais tempo, avance somente quando compreender o essencial.

## Semana 1 — Lógica de programação

**Objetivo:** fortalecer o raciocínio lógico e resolver pequenos problemas.

- **Dia 1:** revisar variáveis, tipos de dados e entrada/saída.
- **Dia 2:** praticar condições com `se`, `senao` e decisões encadeadas.
- **Dia 3:** estudar operadores relacionais e lógicos.
- **Dia 4:** praticar exercícios curtos em Portugol.
- **Dia 5:** estudar laços de repetição.
- **Dia 6:** refazer dois exercícios sem consultar a solução.
- **Dia 7:** revisar dificuldades e registrar aprendizados.

**Entrega da semana:** pelo menos dois exercícios resolvidos e explicados com suas próprias palavras.

## Semana 2 — Primeiros passos em Java e Git/GitHub

**Objetivo:** conhecer a linguagem Java e aprender a registrar a evolução dos estudos.

- **Dia 8:** conhecer a estrutura do bootcamp Itaú — Java com Inteligência Artificial.
- **Dia 9:** estudar variáveis, tipos de dados e entrada/saída em Java.
- **Dia 10:** praticar condições e comparações.
- **Dia 11:** praticar laços de repetição.
- **Dia 12:** conhecer repositórios, commits e histórico no GitHub.
- **Dia 13:** organizar um repositório de estudos.
- **Dia 14:** revisar e registrar um exercício no GitHub.

**Entrega da semana:** um exercício simples em Java documentado, se os fundamentos já permitirem.

## Semana 3 — Banco de dados e APIs

**Objetivo:** entender como aplicações armazenam informações e se comunicam.

- **Dia 15:** estudar o que é um banco de dados relacional.
- **Dia 16:** conhecer tabelas, registros e campos.
- **Dia 17:** praticar consultas SQL simples, como `SELECT`, `WHERE` e ordenação.
- **Dia 18:** entender o conceito de API.
- **Dia 19:** conhecer requisições e respostas HTTP.
- **Dia 20:** observar como uma aplicação consome uma API.
- **Dia 21:** revisar e registrar dúvidas.

**Entrega da semana:** um conjunto de consultas SQL simples e uma explicação de como uma API funciona.

## Semana 4 — Automação e projeto de estudo

**Objetivo:** reunir os conceitos estudados em uma proposta pequena e demonstrável.

- **Dia 22:** escolher um problema simples de vendas, produção ou logística.
- **Dia 23:** descrever o problema e as regras da solução.
- **Dia 24:** desenhar a lógica antes de programar.
- **Dia 25:** implementar uma primeira versão, usando a linguagem que estiver mais confortável.
- **Dia 26:** testar diferentes entradas e corrigir problemas.
- **Dia 27:** organizar os arquivos e publicar no GitHub.
- **Dia 28:** escrever o README explicando o objetivo e o funcionamento.
- **Dia 29:** revisar o código e as anotações.
- **Dia 30:** avaliar o que aprendeu e definir os próximos passos.

**Entrega final:** um pequeno projeto de estudo documentado no GitHub. Não precisa ser complexo; precisa ser compreensível e funcionar conforme o objetivo definido.

## Revisão ao final dos 30 dias

- Quais conceitos consigo explicar sem consultar o material?
- Que exercícios consigo resolver sozinho?
- Quais erros aprendi a identificar e corrigir?
- O que ainda preciso praticar?
- Qual será o próximo projeto?
